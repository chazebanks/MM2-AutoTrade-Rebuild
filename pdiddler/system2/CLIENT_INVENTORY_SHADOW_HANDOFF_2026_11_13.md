## Verified existing source-contract inputs
- The ORIGINAL live scanner `pdiddler/pdiddler3_scanner_MODULE_v6_6_PERF.lua` (main Git blob `d3d3e2d5476b970ec17f4577d8d30d4407a4de64`) already reads the MAIN client's own inventory via `ReplicatedStorage.Remotes.Inventory.GetProfileData` and metadata `Sync.Weapons` / `Sync.Item`.
- Its function `ScannerAPI.getOwnInventory()` returns `inventoryFromProfile()`: `items, total, rawOwned, unmapped, unpriced, badQty, seen, fingerprint`. Each eligible row has exactly `id,cat,name,qty,value,type,page,checkerId,identity,year,event,valueSource`; `identity` is the scanner's 8-segment `metaIdentity` constructed from raw key/page/type/chroma/year/event/item ID/asset metadata. `seen` represents **all owned weapon counts including excluded common items**, and `fingerprint` is sorted `id x count` strings joined with pipe. `items` contains only eligible filtered rows, so it can **never prove a complete tradeable or all-rarity inventory** by itself.

- Accepts a **caller-supplied** 60-second research envelope with the already existing scanner result; envelope must have schema `gingerscope-system2-scanner-snapshot-envelope-v1`, source `PDIDDLER3_SCANNER_GET_OWN_INVENTORY`, `capturedAt` UTC, local nonempty `jobId`, `readOnly=true`, and `inventory` exact original shape.
