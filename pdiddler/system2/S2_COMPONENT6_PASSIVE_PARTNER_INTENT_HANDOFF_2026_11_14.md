## Actual code and original-source trust boundaries
1. `pdiddler/system2/native_partner_intent_observer.lua`: pure Luau, local-only read-only classifier. Obtains current protected C3 `researchContext()` with source hash, offer client revision, owner census freshness and active protected lease/partner/user scope. Requires the same immutable crosswalk schema with **189 historical raw game keys**. Constructs an exact market-name alias index; resolves longest exact item phrases, Chroma variants and collision cases, not fuzzy substring guessing. Eg `Chroma Fang` is mapped to **`FangChroma`** raw key, and `Flowerwood Gun` is distinct from `Flowerwood Knife`.
2. `pdiddler/system2/native_partner_textchat_receiver.lua`: OPTIONAL client listener for Roblox `TextChatService.MessageReceived`, using `TextChatMessage.TextSource.UserId` to identify the current protected trading partner. Never uses `PrefixText` or display-name text as a speaker identity. Actual local username is supplied from `Players.LocalPlayer.Name` at runtime. The owner display-name @alias is allowed only when no other player has the same **display name or username**. Other players, system messages without TextSource, invalid message IDs, unsupported chat channels and whispers involving a third party are discarded. Requires original MM2 PlaceId + JobId, bound P3/P4 lease, local and partner UserIds, and current C3 session.
3. **No-username attribution**: a `RBXWhisper:<localUserId>_<partnerUserId>` between the two exact users is direct; an @-mention of the uniquely resolved owner username/display alias is direct. A public message from the partner following a specific **reviewed local own-offer revision timestamp** (within 12 monotonic seconds) is only `TENTATIVE_IN_CURRENT_TRADE_AFTER_OWN_OFFER` and `personalReplyProven=false`. Without that witnessed revision, public `LF` can be recorded as **general stated interest only**, not a personal counteroffer. If platform-integrated chat withholds message text, the module cannot read it, so it fails closed.
4. **Intent grammar**: explicit `LF`, `NLF`, `not looking for`, `dont want`, `but not`, bounded negation/uncertainty (`maybe`), `what do you want`/short forms, `can you add`, `overpay`, `NTY` or `no thanks`, upgrade/downgrade and `no dupes`, `no seers`, `no pets`, `fewer items`. This is **English-first rule-based evidence**, not an NLP guarantee. `NTY` is a chat-level refusal, not a server trade Decline. `op` is not transformed into an invented seller premium or greedy personality.
5. **Revision-sensitive memory**: at most 48 client messages deduplicated by received `MessageId`; raw message text is not stored or returned. Short-lived item wishlist/avoidance and inventory style preferences persist for up to 120 seconds **within the same bound lease**, visibly tagged as carried from an earlier offer revision. Former offer-specific negotiation indicators count only on that exact client revision; a rollback, lost lease, departed partner, source drift, server hop or inactive C3 session stops or **purges** local client evidence. No cross-account/cross-server tracking or public profile recording.
6. **Research offer-fit overlay**: `compareResearchOptions` checks up to twelve proposed research bundles against the current partner's explicit item requests/avoidance/duplicates, labelling `MATCHES_STATED_ITEM_INTEREST`, `CONFLICTS_STATED_PREFERENCE` or `UNVERIFIED`. It does NOT independently establish that the account owns the outgoing item, the partner owns the requested item, or that C4's bilateral no-loss/identity constraints pass: **C4 is separately mandatory**. The output always sets `canProposeLiveOffer=false`, `actualWillingnessToTrade=false`, `estimatedAcceptProbability=nil`, and `authorizesChat=false`, `authorizesOffer=false`, `authorizesAccept=false`. It cannot send messages, remotes, offers, webhooks or training labels.
