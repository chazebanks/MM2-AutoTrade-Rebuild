# Stage 24 — Existing Part 3 scan timestamps and Stage 17 live-context adapter

**Status:** Draft. Python and Lua integration tests only. No automatic trade placement enabled in the preview loader, no final Accept, no Discord completion claim, no second scanner.

## Problem found

Our Stage 6 scanner export correctly warned that a cached opponent record had *no timestamp proving the underlying scan's completion*. Stage 23's strategy permit could match a valid-looking cached player inventory and a fresh Supreme price without proving that those were observed in the same job recently. Rechecking a cached list against itself does not establish recency.

## Changes

1. The existing Part 3 scanner now annotates **successful stable-read publications** only with a small `scanProof` record: local monotonic completion time, server job ID, exact player ID, fingerprint and increasing scan sequence. Whitelist/blacklist rules, remote calls, GUI, bot detector and server navigation are unchanged. Unknown, invalid, incomplete, or failed scans do not get a proof. This is a local client observation, **not** authenticated server proof.
2. `new_part4/p4_live_context.lua` is a read-only bridge using existing `getRecord()`, `getVerificationState()` and `getOwnInventory()`—no invented opponent API. It rejects records that are scanning/retrying, belong to another player/job, have mismatched fingerprints/sequences or are older than the configured 2–120 s window (default 30 s). It separately bounds the own-inventory read and invalidates the context after any market version/source change.
3. The adapter compares exact canonical (page, checker ID, display name, category, type, quantity) identities against the **existing Supreme profile** and converts only supported evidence to Stage 16's exact cent-price, demand and stability format. It neither invents flippability nor infers narrow price ranges.
4. Stage 23 `validate()` now requires the current observer's decoded `theirItems`, not a cached copy of the earlier decode; Stage 22 and the replacement controller forward those diagnostics.
5. The replacement controller can optionally use this adapter if an **external, explicitly injected** strategy configuration sets `nativeEvidence=true`. It does **not** generate a trade candidate or set `allowed=true`. The ordinary preview still calls `p4.run(scanner,profile)` without a strategy/placement configuration.

## Source freshness remains a separate blocker

The existing pinned Supreme snapshot `supreme-2026-11-04-97613e277b36` expired 2026-11-05T21:55:32Z. The website still displays a last-value-update date of November 4, 2026 as of this review. This stage does **not** relabel the old profile, extend its TTL, or misrepresent prices as independently updated. A new source-backed snapshot should be generated using the existing snapshot refresh tooling, with provenance, checked item counts, and real fetch time. None has been generated by this stage.
