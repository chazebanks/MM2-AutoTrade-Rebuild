## External constraints and independent assessment
- Official Roblox [RemoteEvent class docs](https://create.roblox.com/docs/reference/engine/classes/RemoteEvent) establish StartTrade/UpdateTrade callbacks are received from server-side fired RemoteEvents, and may be queued until a handler connects. No MM2 trade transaction ID is guaranteed.
- [Unofficial myCompiler MM2 script](https://www.mycompiler.io/view/4ySHMGgjq9h) assigns LastOffer=os.time() on offer changes. This is **untrusted client-side reconstruction/spoof code**, not evidence of actual MM2 server semantics. Consequently LastOffer is a plausible edit timestamp, **not** an authenticated nonce.
- A source-independent impossibility: if two trade sessions have the same player pair and same offer snapshot, and no fresh session identifier or authenticated server result is supplied, a delayed event from session A is observationally indistinguishable from an identical current event from session B. More GUI polls do NOT solve this.

## One falsifiable Stage45 question
A player reference or a scalar field is **not a session identifier** without evidence of uniqueness, freshness and server-provided association. Does **native StartTrade.OnClientEvent** supply structured callback arguments containing player references or any scalar candidate that might later help discriminate sessions? Stage33 did not record argument payloads, so this is genuinely new evidence rather than repetition.

NEW purely functional module `p4_stage45_start_trade_payload.lua` records ONLY a bounded list of primitive TYPE enums (up to six arguments), count of exact local/partner player object references and counts of unclassified string/number primitives. It does not inspect nested table contents, disclose raw names, keys, numbers, userdata, account IDs, session values, or declare any scalar a session token. Every authority field remains FALSE.

## First REAL Stage45 Delta result and narrow timing revision (2026-11-07 Eastern)

[User-supplied first native JSON recorded in PR84](https://github.com/chazebanks/MM2-AutoTrade-Rebuild/pull/84#issuecomment-6715337232): one `StartTrade` callback (`receiptCount=1`) occurred while a trade GUI was already visible (`eventBeforeVisibleGui=false`); old script stopped `GUI_VISIBLE_BEFORE_START_TRADE_RECEIPT` **before inspecting any callback arguments**, with `listenerCount=1`, `listenersDisconnected=1`, `cleanupComplete=true`, `status=INCOMPLETE`. This does NOT reveal whether that receipt was delayed, stale, the same session, or a particular callback-argument type. All authority fields were false. There was no video. Do not label as proof StartTrade always follows GUI: Stage33 saw the reverse ordering in a separate manual test.

**Root cause in OUR probe:** the prior unconditional `if visibleCount~=0 then finish(...)` assumed the callback must predate a visible GUI for even an untrusted type census. This unsupported *diagnostic gating assumption* prevented observing a real callback. The zero-authority type-only research question does not require server/session causal attribution.

**Specific revised predicate:** a single callback before GUI remains allowed. When the callback runs with exactly ONE visible trade root, require its unique human-readable GUI partner label resolve to exactly one Player object; privately capture that exact root, label object, unexported original label text, and partner. On later stable empty-offer GUI frame, require **the same root/label/partner and unchanged original label text**, both offer signatures empty and both Accept indicators false. Reject any extra visible root, an unbound or changed label, replaced/hidden root, duplicate callback, queued pre-arm event, owner/JobId changes, unexpected offer mutation, Accept, or listener-cleanup failure. Report one of `callbackGuiMode=EVENT_BEFORE_VISIBLE_GUI_CLIENT_ONLY`, `GUI_VISIBLE_AT_CALLBACK_CLIENT_ONLY`, or `NOT_OBSERVED` together with `eventBeforeVisibleGui`. This is an observational timing classification ONLY, **not session ID or proof of causal association**.

**Regression matrix added to real whole-loader fake-game Lua harness (run through Python):** one callback arriving on same tick as a newly visible, uniquely bound GUI now permits TYPE-ONLY census; wrong partner label, duplicate visible roots, disappearing root, partner label change, nonempty offers, premature Accept all fail closed. Older event-before-GUI and all 31 existing scenarios remain tested, for **37 whole-launcher scenarios** total, plus the unchanged 17 pure Lua cases and 320 Python-driven real Lua randomized payload cases.
