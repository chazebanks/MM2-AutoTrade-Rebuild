# Stage52 — Quarantine unsafe scheduled MM2Values publication; audit live source evidence

## One verified high-risk bug, NOT another Delta probe
The repository's `.github/workflows/refresh-values.yml` previously ran daily (`15 18 * * *`) with **`contents: write`**, executed `scripts/update_values.py`, and **`git add values/mm2values.lua; git push`**. The updater used `datetime.now(timezone.utc).strftime("%Y-%m-%d")` as exported `updated` and set `complete=true` after scraping a MINIMUM of 100 Godly / 16 Ancient / 40 Chroma rows. Those conditions do NOT prove the publisher updated values today, that each item/variant is correct, or that the scraper captured the complete live list. Scheduled code could therefore transform a stale, wrong, incomplete-above-minimum or misassociated scrape into an apparently current automatically committed price catalogue.

This is source-backed repo code, **not evidence a particular daily job succeeded**. No assertion that the live autotrader was using the generated Lua value table; production script remains unmerged. The real Stage50 Batwing preprofile key correlation is already complete, and Stage51 scanner mapping-method provenance fix is verified in separate draft PR90; **do not repeat Stage50**.

## Narrow correction on Stage52 draft (stacked on Stage51 draft PR90)
1. Rewrite **only the previously scheduled updater** into a deliberately **audit-only source evidence fetch**; no path writing to `values/mm2values.lua` and **no `--publish` mode**. It fetches the three original `https://mm2values.com/?p={godly,ancient,chroma}` sources with Cache-Control request hint, keeps individual raw-response **SHA256**, retrieval times, exact source URL, tier row counts, candidate name/category/value rows, and a row-by-row deterministic delta relative to the unchanged saved baseline. Correctly names `publisherUpdatedAtUtc=null`, `baselineGeneratedDateUnverified`, `minimumCountChecksPassed=true`, `fullCatalogueCompletenessVerified=false`, `exactMM2WeaponIdentityVerified=false`, `liveReady=false`, `canPublishPrices=false`, `authorizesAccept=false`, `authorizesTrade=false`. A minimum count cannot itself prove completeness.
2. An error in any one source page, date shape, SHA format, item category, name case collision, invalid price, missing/duplicate tier or mismatch between reported and parsed row counts causes the entire audit to stop **before any candidate file is written**. The old live price file remains byte-for-byte intact on source failures.
3. The daily/manual workflow now uses `permissions: contents: read`, runs `python scripts/update_values.py --audit-only --output-dir "$RUNNER_TEMP/mm2_market_refresh"`, uploads **`source_audit.json` and `candidate_NOT_FOR_TRADING.json`** as an artifact using `actions/upload-artifact@v4` (14-day retention). It cannot `git push` or silently redate a price file. The archived candidate **is review-only**, never used as real quote authority, and manual provenance/ID/year/Chroma/price/demand/stability comparisons remain required before any future approved price publisher is written.
4. No user executable Delta code, no production trader/acceptance, inventory transfer, webhook, bot avoidance, legacy +15 profit policy, old 90% accept, timed sweetening or Gingerscope economic strategy changed.
