## One narrowly scoped Stage52 change — observation still automatic, authority never automatic

1. `scripts/update_values.py` STILL retrieves **all THREE original MM2Values pages automatically** and parses raw rows, while keeping per-page HTTP **raw HTML bytes**, SHA256 verified against original captured bytes, source URL, retrieval UTC, exact tier row counts, candidate item names/categories/values and deterministic diff to the stored baseline. It sets `publisherUpdatedAtUtc=null`, not crawl time. Checks missing/duplicate tiers/keys, case-folded duplicate names, unknown Chroma variants, invalid/boolean/negative values, wrong tier URL or source hash, unexpected row counts and fail before writing live values on malformed sources. Candidate status ALWAYS `RESEARCH_ONLY_NO_TRADING_AUTHORITY`.
2. With `--audit-only`, no value-file writing at all; uploads five audit artifacts: `source_audit.json`, `candidate_NOT_FOR_TRADING.json`, `source_godly.html`, `source_ancient.html`, `source_chroma.html`.
3. Scheduled `--publish-research-only` retains automatic observations but publishes **only** if **exactly the same name+category identity set** exists before and after the source read, with each price change bounded by a parser-anomaly threshold `max(30, 30% of previous value)`. This is NOT a trading profitability rule or an independently proven market stability guarantee. New/removed names, category/variant switches and larger jumps return `REVIEW_REQUIRED` (nonzero), leave saved file untouched and still retain all source artifacts for manual inspection. This intentionally pauses *unusual legitimate* publisher changes until reviewed.
4. The automatically generated `values/mm2values.lua` remains useful as **research observations only**, but now **`updated="PUBLISHER_DATE_UNKNOWN"`**, `retrievedAtUtc=<actual retrieval time>`, `publisherUpdatedAtUtc=nil`, `provenanceScope="OBSERVED_MM2VALUES_PAGES_NOT_ID_AUTHENTICATED"`, `complete=false`, `liveReady=false`, `authorizesTrade=false`, `authorizesAccept=false`, `mayReportProfit=false`, and SHA256 of each original source page. Existing `items[name]={value,category}` and `M.get(name)` data access remain so research UI can still display observations; however these observations **never** authorize live trading.
5. File replacement is atomic via temporary file and `os.replace` after all checks. For identical values, the old legacy file is migrated once to truthful provenance; thereafter unchanged observations do **not** rewrite the file just to advance a date. On a valid bounded price change a new observation is automatically committed, without claiming the publisher's date or server authority.
6. Workflow retains daily + manual dispatch and guarded `git push` after `python scripts/update_values.py --publish-research-only` succeeds. The job-specific GitHub token requests `contents: write`, while the workflow top-level defaults to `contents: read`. `actions/upload-artifact@v4` runs `if:always()` and retains five original/candidate evidence files 14 days even if publication is blocked. DO NOT mistake GitHub Actions successful CI for deployment to main: **PR91 is DRAFT, STACKED and UNMERGED**, so main's old workflow remains active until reviewed/merged.

## Tests and failure modes

Tests cover 3-tier coverage, forged publisher dates, full exact HTML SHA replay, duplicate and cross-tier keys, Chroma shape, invalid quantities, baseline tampering, audit-only unchanged source file, error-before-any-write and abort-on-one-missing-source, scheduled pipeline gating, 700 seeded deterministic item diffs, and publication-migration/blocked anomalies and idempotent identical-source reruns. Additionally, generated Lua can be run in real Lua5.4 and must yield `M.get` rows with `complete=false, liveReady=false`, no trade/Accept, `publisherUpdatedAtUtc=nil`.

**Known parser limitation:** The current `collect(kind)` extracts a value by nearby visible text, not an authenticated MM2 raw weapon/checker-ID instance. Even full name-set equality cannot rule out same-name wrong-year variants or a publisher changing semantics. That is why `complete` and `liveReady` remain false, and a new expiring exact checker-ID market profile needs separate explicit, independently reviewed evidence. The margin `max(30,30%)` is a conservative **data anomaly review hold**, not the old +15 Gingerscope profit floor, not a source-backed estimate of expected volatility, and not permission to execute trades.

**No live MM2 execution, no manual Delta probe, no auto final Accept, no profit/webhook, no server settlement or Gingerscope trade strategy change.** Actual Stage50 Batwing client owned-key correspondence is already [verified in PR89](https://github.com/chazebanks/MM2-AutoTrade-Rebuild/pull/89#issuecomment-6715971733); Stage51 checker mapping provenance in [PR90](https://github.com/chazebanks/MM2-AutoTrade-Rebuild/pull/90) remains separate.
