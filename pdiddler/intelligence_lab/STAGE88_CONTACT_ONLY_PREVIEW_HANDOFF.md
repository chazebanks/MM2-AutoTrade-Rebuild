## Test run and permissions

It starts the original T4 scanner, then the *real* Stage87 controller in a 35-second bounded **observation window**. The controller's `refresh()` reads own local inventory through the existing scanner's rate-limited own-profile read; `queue()` counts reachable, no-items and unknown players, but **NO** outgoing authorization, `sendAndWatch`, `TradeRequest`, physical mouse/controller clicks, Part4 offer, Part5 teleport, final Accept or webhook endpoint is ever loaded or called. The original scanner may keep running nontrading read-only background listeners after the 35 seconds; rejoin to clear it.

The only published summary is one `[GINGERSCOPE STAGE88 CONTACT PREVIEW]` JSON line with aggregate counts, source/identity/trade authorization flags FALSE, no raw owned keys, names, user IDs, session IDs or offer data. If Delta supports clipboard it copies this one bounded aggregate marker. The scanner's own visible GUI can show people names as normal local gameplay, but the summary deliberately contains none. If another script/session owner is present, wrong game, source unavailable, job/PlayerGui replaced or trade GUI active, the preview fails closed.

**Do not mistake local `reachable` for permission to send a request**, confirmed partner inventory, a fresh price, actual offer value, trade completion or market learning. The Stage88 native preview is strictly a *read-only contact-display diagnostic*. It does **not** run the outgoing rotator, and user must not expect it to send any trade requests yet. This is the bounded test necessary before the next separate physical request handoff.
