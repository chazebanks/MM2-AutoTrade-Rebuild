## How it differs from the earlier tests

- Stage59: an operator-confirmed ALT→MAIN manual exchange gave two independent client +/-1 eligible readback reports, but **never included AcceptTrade callback argument shapes** in those reports. It satisfied the limited two-client corroboration task, not a server receipt.
- Stage61: current native iPad captured `BOOLEAN_FALSE` at +21.1 sec with one argument and `BOOLEAN_TRUE` at +21.4 sec with a second one-entry TABLE while GUI was bound, then GUI closed. **No scanner or postclose inventory readback in this same Stage61 run**. This matched the archived MM2 v1456 [TradeModule client callback branches](https://github.com/tlredz/decompiledGames/blob/0552a0f3502217a1cf89df66be9bd0f153e47fa4/murder-mystery-2/v1456/ReplicatedStorage/Modules/TradeModule.lua) at a shape level; it does not establish whether this exact Stage61 run visibly completed.
- Stage62: a pure offline fail-closed classifier forbids pretending those independent different attempts are the **same** trade. [PR114](https://github.com/chazebanks/MM2-AutoTrade-Rebuild/pull/114).

Stage63 is **one executable read-only adapter**, not two competing observers. It starts one single `AcceptTrade.OnClientEvent` listener, then loads the exact immutable **Stage59 role-neutral own-inventory observer** at Git commit `54b97f65290ce038910436e27600be6a2c4a005e`, expected Git source blob `e1324b157126ff3cdc2928595b262e7a64e2150e`. The pinned old Stage59 core owns the ONLY scanner, native Stage9 GUI observer, Stage28 timeline, Stage29 own-inventory baseline and two postclose own reads, and Stage30 three result-named listener census. The adapter does **not** read/invoke an extra inventory RemoteFunction, does not run Stage61 concurrently, does not fork Stage59's native observer code or modify any prior device-tested source.

## Specific safeguards

- MAIN GUI is bound only after the pinned core reports its native baseline and `OBSERVING_CLOSE` state. - Accept callback consumes ONLY argument count, first boolean type/value, second arg `TABLE`/other and its **bounded length**, plus approximate relative time (0.1 second). It does not traverse, retain, hash, log or upload any callback item/weapon/player values.
