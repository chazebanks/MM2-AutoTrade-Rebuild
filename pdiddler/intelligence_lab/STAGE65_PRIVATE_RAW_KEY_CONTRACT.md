That suggests a *candidate* row `{rawKeyString, quantityNumber, categoryString}`, but we have **NOT** captured native current-2026 element types or established that `item[1]` is the actual `Weapons.Owned` raw key. Never substitute the visible weapon label, a market checker ID, an alias or icon art as proof.

The **real pinned** Stage59/63 scanner [v6.10](https://github.com/chazebanks/MM2-AutoTrade-Rebuild/blob/001d228a407076d3cc411a5a7132b0076ec4c027/pdiddler/presentation/pdiddler3_scanner_MODULE_v6_10_CURRENT_PRESENTATION.lua) reads `GetProfileData` (one own inventory RPC through bounded scanner gate); it stores `Weapons.Owned` map raw key as `items[].id=tostring(rawId)`, also computes a mutable `checkerId` through alias and fuzzy market matching. ## New Stage65 contract: STRICTLY offline Lua primitive equality

New pure helper `pdiddler/intelligence_lab/p4_stage65_private_raw_receipt_equality.lua` takes **hypothetical** in-memory `beforeOwned`, `post1Owned`, `post2Owned` raw `Weapons.Owned` count maps, `callbackFirstArg=true`, same-client GUI scope flag, and a `receivedItems` table with EXACTLY ONE triplet `{stringKey, integerQuantity=1, "Weapons"}`.

- Performs literal, case-sensitive string primitive matching against EXACTLY ONE changed positive raw owned key with delta +1, zero losses, and two identical post-close raw maps; no fuzzy aliases, checker price, catalog name, hashes, icon, numerical cast, or normalization.
- Refuses additional/unknown fields, malformed or leaked IDs, second item, other category, invalid quantity, changed extra key, inconsistent readbacks, missing records, oversized strings/counts or self-attested authority.
- Returns only `PRIVATE_RAW_PRIMITIVE_EQUALITY_CLIENT_ONLY` (or `INCONCLUSIVE`) with boolean `rawCallbackKeyEqualsOwnGainedKey`. **Never outputs the raw key**, account, item type/name, price, or any data copied from caller. ALL server/settlement/transaction/offer/market/identity/completion/profit/Discord/auto-Accept authority flags fixed FALSE, including `callbackKeySemanticIdentityProven=false` even on equality.
- Does not read a live profile, remote, game, network or clipboard; no native iPad/Delta launcher. A caller cannot self-declare “verified” or supply fake transaction evidence and make the result authoritative.

This is intentionally a **contract feasibility test**, NOT a current native Stage63 callback-key proof. Current Stage63/Stage61 collectors read only callback **type and TABLE length**, not element values. The historical triplet structure is a hypothesis to test with a future privacy-bounded **element type + local equality-only** observer, ideally piggybacking the already verified one-scanner core. Do NOT add a second inventory RPC or run Stage59 and Stage61 concurrently.
