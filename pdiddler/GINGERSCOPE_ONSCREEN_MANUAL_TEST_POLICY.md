# MM2 / pdiddler: Mandatory in-game instructions for future manual diagnostic tests

**User-requested durable workflow rule (Nov 10, 2026). This rule applies to future conversations, Codex/Copilot agents, ChatGPT-created scripts and every new native iPad/Delta test that requires the user to take timed manual actions. Read along with `pdiddler/GINGERSCOPE_LATEST_CHECKPOINT.md` before building any new test.**

## Required behavior

1. Whenever the script asks the user to open a trade, add/remove an item, change menus, select an account, or perform any sequence of manual actions, **display the exact CURRENT instruction on the iPad's game screen** in a readable, compact, high-contrast overlay. Do not require the user to keep the Delta console open to discover each step. Also print the same step to the console and retain a sanitized JSON report.
2. The overlay must **not overlap, obscure, intercept taps on, or be hidden underneath MM2's actual TradeGUI, Accept, Decline, offered item slots, or other required controls**. Compute the current viewport and **physical GUI bounds**, then choose a non-overlapping safe region with margins. Re-evaluate after trade opens, when the GUI moves, during orientation/resolution changes, and before every prompt. A fixed top-right position alone is NOT acceptable, and freely dragging the panel across trade controls violates this requirement.
3. On mobile/iPad honor OS safe areas/insets and Roblox topbars. The card should be small, readable and noninteractive while the test runs; an optional dismiss X is permitted ONLY after test completion. A high ScreenGui DisplayOrder can keep the card visible, but NEVER use display order to justify covering trade content.
4. If the viewport/trade bounds are unavailable, the panel could collide with the trade, or **no safe free region exists**, **hide the panel and fail closed with INCONCLUSIVE** (e.g. `ONSCREEN_GUIDE_NO_SAFE_SPACE_OUTSIDE_TRADE`). Never fall back to obscuring Accept/Decline or continuing manual actions without a visible instruction. The console can explain the failure.
5. The panel must clearly distinguish **MAIN** versus **ALT** instructions, include the active numbered step, warn **NEVER PRESS FINAL ACCEPT** in read-only tests, and replace the instruction only when its prior condition is verified. On completion, show PASS/STOP with a way to dismiss and direct the user to copy the sanitized report.
6. This is **UI only**, not permission to initiate trade requests, add or withdraw items, Accept/Decline, hop, price weapons, report completed trade, or send Discord. Client-visible UI evidence never establishes server settlement or a verified raw item ID.
7. For each new diagnostic, run **real Lua mock integration tests** exercising the actual wrapper and the original pinned trade GUI observer. Explicitly test several screen dimensions, trade window placed left/right/center, window movement, zero-sized/full-screen trade bounds, missing camera, panel creation failures, and inadvertent overlap or touch interception. Run Python/Lua regression and exact GitHub CI; do not claim actual iPad layout verified until the user tests it.
